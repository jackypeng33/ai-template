## 2. 产品定义与问题陈述

一句话：面向英语娱乐分享用户，将自己和朋友的两张照片，配合一段固定原创 Rap，生成可下载的 8 秒双人表演视频。

用户希望制作包含自己和朋友的有趣视频，但不愿自己拍摄、演唱或学习剪辑。本产品首先验证：用户看到真实生成效果后，是否愿意为自己的版本付费，并下载结果？

目标用户是英语市场的普通娱乐分享用户，不以专业音乐制作、品牌广告交付或长期创作工作流为首版目标。首批用户来自短视频平台上的真实样例，首轮集中一个平台，具体平台待定。

## 4. 核心流程

```mermaid
flowchart TD
    A[短视频平台真实样例] --> B[独立落地页]
    B --> C[选择两张照片并预览左右角色]
    C --> D[点击购买并登录]
    D --> E[恢复草稿并确认素材、规格和价格]
    E --> Q{上传照片审核}
    Q -->|通过| F[PayPal 支付]
    Q -->|拒绝| C
    Q -->|待审或异常| R[等待审核或重试审核]
    R --> Q
    F --> G{服务端确认付款}
    G -->|成功| H[自动创建生成任务]
    G -->|取消或未完成| E
    H --> I[查看真实任务状态]
    I --> J{处理结果}
    J -->|生成成功| S{成品视频审核}
    S -->|通过| K[播放、下载、发送完成邮件]
    S -->|拒绝| T[阻止交付并转人工处理]
    S -->|待审或异常| U[保持不可交付并恢复审核]
    U --> S
    J -->|明确技术失败| L[返还一次生成机会]
    L --> M[更换或保留照片，手动再次生成]
    M --> I
    J -->|长时间状态不明| N[继续查询原任务并转人工核查]
    N --> O[可申请退款，人工决定处理结果]
    K --> P[效果不满意时提交问题反馈]
```

### 4.1 落地页

必须包含产品用途、真实效果样例、两张照片选择器、左右角色说明、固定规格、最终价格、“支付并生成”操作、简短步骤、FAQ、失败及效果误差说明、下载期限、隐私说明、登录和“我的视频”入口、客服入口。

样例必须反映实际使用的模型、模板和规格。不得以经过额外修脸、换音轨等处理的样例暗示普通订单能直接达到相同效果。

### 4.2 照片与登录

- 两个位置分别选择一张单人照片，支持缩略图、替换和移除。
- 明确第一个人物在左侧主唱，第二个人物在右侧配合。
- 预览仅表示素材和人物顺序，不是免费生成视频。
- 缺失、损坏或不符合要求的素材必须在付款前提示。
- 上传照片须通过 SeeAPI 内容审核后才能用于付款和生成；NSFW 素材拒绝使用并提示替换，详见第 14 节。
- JPEG、PNG、WebP 为格式基线；大小和尺寸限制在实现前明确并展示。
- 登录往返后恢复照片和顺序；恢复失败或素材失效时要求重选，不能用无效素材进入付款。

### 4.3 付款与自动生成

付款前展示照片、人物分工、固定模板和音乐、8 秒/9:16/720p、最终价格、技术失败处理和保存期限。

- 按钮明确表达“支付并生成”。
- 付款前保存有效草稿，订单绑定该版本素材；后续编辑不改变已付款任务。
- 仅凭服务端确认的支付成功启动生成，不能凭返回 URL 或用户批准支付发放权益。
- 关闭返回页不影响已付款订单履约，用户回来后能找到任务。
- 重复点击、通知重发、刷新不能导致重复履约或重复生成。
- 支付取消不生成；支付状态未明确时显示确认中，不诱导重复购买。

### 4.4 等待与结果

| 状态 | 用户体验 |
| --- | --- |
| 支付确认中 | 等待确认，可查看订单 |
| 等待提交或排队 | 已记录任务，无需重复操作 |
| 生成中 | 可以离开页面 |
| 处理异常、核查中 | 状态不明，可反馈或申请退款 |
| 内容审核中 | 素材待审时不可付款或生成，视频待审时不可播放或下载 |
| 内容未通过审核 | 提示更换输入素材；成品拒绝交付并提供客服入口 |
| 已完成 | 视频审核通过后播放、下载、明确到期时间 |
| 明确失败 | 失败说明及已返还的生成机会 |
| 视频过期 | 不可下载，仍能查看订单及联系客服 |

不编造百分比，不承诺未经验证的完成时间。完成后发送邮件；邮件失败不影响任务成功或账号内获取结果。

### 4.5 技术失败、效果反馈和异常等待

明确技术失败且没有可用视频：原任务只返还一次机会；用户可以更换或保留照片，手动开始新任务；新任务关联原订单和补发记录。不得形成无人值守的无限自动重试。

已出片但相似度、口型或表演不满意：结果页提供“反馈问题”，自动关联订单，允许填写描述及补发/退款诉求。申请不等于自动批准，通过邮件人工处理并记录决定。视频到期后，订单仍保留客服入口。

超过待确定的处理阈值：转人工核查并继续查询原任务，提供退款申请入口。等待超时不等于生成失败，不自动返还或重发。已退款或补发后原任务又成功的处理规则须在上线前明确，避免重复补偿。

## 5. 音乐、隐私与保存期限

固定原创音乐的授权必须覆盖商业生成服务、多位付费用户重复使用、用户下载并发布包含音乐的成品。不能只凭“可商用”字样认定覆盖所有用途。最终音频必须参与效果验证。

| 数据 | 规则 |
| --- | --- |
| 已结束任务的照片 | 任务结束后 24 小时内从本系统删除 |
| 生成视频 | 保留 7 天，到期后不可下载 |
| 订单与处理记录 | 视频过期后仍用于订单查询与客服处理 |
| 供应商侧素材 | 另行核实、披露，不把本地删除宣称为所有副本删除 |

草案建议视频保留期从结果可用时间起计算，并在结果页及完成邮件展示明确到期时间。

未付款/取消购买草稿、长期状态不明任务的照片清理期限尚待确定，不能无限保留。不得对外声称这两类清理已落实。

## 6. 技术约束与复用边界

- 在当前 Next.js 项目内新增独立入口，优先复用登录、PayPal、邮件、存储和记录查询能力。
- 现有一次性积分包不等于完整的按次视频购买能力；仍需明确订单、素材快照、生成任务和补发机会之间的关联。
- 产品购买流程不展示通用积分包、订阅及无关 AI 功能。
- 使用 KIE Seedance 2.0 Mini，服务端固定模型和模板，不照搬对标站其他模型的能力。
- 密钥仅存于服务端；用户只能访问自己的素材、订单和结果。
- 任务处理、邮件通知、结果保存与清理不能依赖浏览器持续打开。
- 提交结果不明时不自动再次调用创建任务；保留可追踪状态并核查原任务。
- 付款履约、失败返还、人工补发必须防止重复执行，保持账目与权益一致。
- 真实生成仅由明确授权的测试，或用户购买/使用补发机会触发。

现有文档实测基线为 4 秒、480p、16:9。本产品的 8 秒、720p、9:16 需另行验证，不能沿用前者的成本、耗时或质量承诺。

## 7. 明确不做

- 自带音乐、音频裁剪、AI 写歌、声纹克隆。
- 双人轮流演唱选项、合照拆分、单人模式。
- 多舞台、多模板、Effects 特效目录。
- 自定义提示词、动作参考视频。
- 时长、清晰度和画幅选择器。
- 免费生成预览。
- 订阅、多档积分套餐、多支付渠道。
- 批量生成、多候选结果。
- 视频编辑器、自动发布到社交平台。
- 完整工单中心、多语言推广。
- 重做整个 SaaS 模板网站。

## 8. 开发前质量门槛

使用最终音乐和模板，对 5 组不同人物素材验证：素材获适当授权；每组只生成一次；统一 8 秒、720p、9:16；记录所有结果、实际费用、等待时间、输出信息和人工评价；至少 4 组合格再推进该效果的收费版本。

单组要求：

- 两个人均可辨认，无明显脸部融合、人物缺失或身份交换。
- 双人构图不明显裁掉关键面部。
- 左侧主唱口型无明显持续错位，右侧符合配合者定位。
- 音画正常播放，时长与约定相符，允许正常编码差异。
- 手机观看效果达到真实样例展示水平。

5 组验证是首轮门槛，不是长期成功率证明。不通过则先调整模板或产品承诺，再推进网站开发和推广。真实测试须先落实素材与预算，不因确认本文自动执行付费调用。

## 9. 成功标准

首轮观察两周：至少 10 位非亲友用户付费；至少 90% 的付费任务成功交付可播放、可下载的视频；至少 5 位付费用户实际下载。

统计要求：

- 内部测试、亲友支持单独标记。
- 技术交付与满意度分别记录，投诉与补偿不能忽略。
- 首次任务和补发任务分别记录，不能以补发成功掩盖首次失败。
- 记录访问、选素材、登录、支付、生成、下载漏斗。
- 记录生成、支付手续费、存储及补偿成本。
- 下载不等于社交分享。
- 流量不足时延长观察，不直接判定无需求。

1. 落实音乐、人物测试素材和验证预算。
2. 执行 5 组效果验证，记录质量、成本和耗时。

4. 实现独立落地页及购买、生成、结果、补偿最小闭环。
5. 按验收清单验证后，开始首轮推广与两周观察。

## 13. 开发启动补充决定（2026-10-27）

用户提供 `inputs/left.png`、`inputs/right.png`，授权准备其他素材与音乐，按对标文档定价并进入开发。随后明确：先不要调用 API 生成视频。此后指令覆盖第 8、12 节中“先完成真实验证再开发”的执行顺序；质量验证仍是收费上线门槛。

- 独立入口 `/rap`，工作品牌 BOOTH，可后续替换。
- 对标文档 Mini 720p/8 秒为 6 积分；最小包 $9.99/10 积分，折算 $5.994，取单次 $5.99 USD。不是把最小包价格直接当单次价格；真实毛利尚未验证。
- 先提供原创程序化节拍与英语合成参考人声的 8 秒音乐草案，提供试听及素材来源；不是已确认商业授权的最终人声母带。
- 静态概念海报必须标注非真实生成视频。不得将它制作成假模型成果或冒充质量验证。
- 未付款上传草稿保留 24 小时；长期异常输入最多保留 7 天；结果从可用时间起保留 7 天。
- 30 分钟未完成先标记核查，继续查询原任务；此为可调整的初始运营阈值，不是完成时限承诺。
- 生成与收费开关默认关闭；开发、自动化测试使用模拟响应和隔离数据库，不执行真实视频调用、支付或退款。


## 14. NSFW 内容审核补充决定（2026-11-05）

本节为新增 MVP 必须需求，尚待实现与联调。采用 SeeAPI 对上传素材和生成视频实施审核，拒绝 NSFW 内容。本次仅更新文档，不授权真实审核或视频生成调用，不开启生成、收费、质量或音乐授权开关。

### 14.1 审核范围与流程

- 当前用户输入为两张照片，每张独立审核；上传文件先进入私有隔离存储，待审与被拒绝素材不能作为有效生成素材。服务端在创建支付订单、启动生成及使用补发机会时校验素材审核结果。
- 审核绑定实际使用文件的不可变版本或内容哈希；替换、修改或重新规范化照片后需重新审核，不能沿用旧结果。付款订单绑定已审核的素材快照。
- 所有生成结果（含补发任务）在交付前审核。视频先存入私有隔离存储，审核通过后才能标记可交付、播放、下载和发送完成邮件；不能通过供应商 URL 或其他媒体接口绕过审核。
- 结果保留 7 天从审核通过且实际可交付时开始计算；拒绝视频在审核结束 24 小时后清理，待审或异常隔离结果最多保留 7 天。
- 本次不增加用户上传视频或音频功能。固定音轨仍需上线前人工检查内容与权利，视觉 NSFW 审核不能替代音频内容或音乐授权审核。

### 14.2 SeeAPI 接入依据

官方文档核对日期：2026-11-05。

- [图片审核](https://www.seeapi.com/docs/nsfw-filter/image-moderation/)用于照片；接入基线为 `nsfw-filter` / `image-moderation`。官方另推荐 Image 2.0，是否升级须在实施时核对契约和效果。
- [视频审核](https://www.seeapi.com/docs/video-nsfw-filter/video-moderation/)用于成品；模型与端点为 `video-nsfw-filter` / `video-moderation`，供应商为 `seeapi`。支持 HTTPS MP4/MOV，最长 30 秒、最大 100 MB，采样范围为 8–32 帧。
- 提交使用 `POST /v1/inferences`，服务端 Bearer 密钥与 `Idempotency-Key`；使用 `GET /v1/inferences/{id}` 获取最终结果。HTTP 202 仅表示受理，任务 `succeeded` 也不等于内容通过。
- `result.data.flagged=true` 或 `reason=content_policy_blocked` 必须拒绝。视频放行还要求有效完整报告、`sampling_complete=true`、无 NSFW 检出及帧记录一致；缺失、矛盾或不完整结果均不得放行。
- 视频是抽帧检测，存在漏检与误判，不能宣传为逐帧检查或绝对安全。采样数量、阈值与严格模式需用代表性素材校准并版本化；上线前确认审核成本。

### 14.3 状态、异常与权益

- 审核状态独立于生成状态，至少区分待审、审核中、通过、拒绝和审核异常。仅服务端依据可信最终报告更新放行状态。
- 网络错误、超时、服务不可用或余额不足均保持不可用，并提供审核恢复或人工处理入口；不得当作通过，也不得为了重试审核重新生成视频。
- 同一审核请求重试保持相同请求体和幂等键；素材或审核策略变化产生新审核版本。重复通知与轮询不得重复交付、发邮件或补偿。优先服务端轮询；如采用回调，须完成真实性校验并以服务端查询核实结果。
- 输入被拒绝时提示用户更换照片，不发起付款或生成。成品被拒绝时阻止交付，记录订单并转人工处理；不自动归类为技术失败、不自动返还机会或无限重生成。退款或补发规则须上线前明确，并沿用订单锁和幂等补偿记录，不改变通用积分。

### 14.4 隐私、记录与验收

- 素材及结果保持私有，仅向 SeeAPI 提供有效期覆盖审核处理的临时签名 HTTPS 地址；不得为审核把客户媒体放入 `public/` 或公开桶。隐私条款须披露审核供应商及核实后的留存规则。
- 审核记录保存媒体版本、所属用户/订单/任务、供应商任务 ID、策略版本、判定、必要原因、时间和重试信息；新增表使用 `rap_*` 命名。日志不得包含密钥或完整签名 URL，敏感报告仅授权管理员可见。
- 验收覆盖：任一照片拒绝时阻止付款和生成；换图重新审核；补发同样审核；成品拒绝时禁止播放、下载和完成邮件；超时、空报告、不完整采样及策略拦截不可放行；重复处理不重复交付或补偿；越权访问失败；审核通过后才启动结果保留期。
- 开发测试使用模拟审核响应。收费上线前完成双阶段审核实现、受控联调、阈值校准、异常恢复、清理期限和拒绝后的客服规则；未具备审核能力时不得开启收费与生成。
