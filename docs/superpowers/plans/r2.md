# 任务：为当前项目正确接入 Cloudflare R2 对象存储

你是一名资深 Next.js、TypeScript、Cloudflare R2 和 SaaS 架构工程师。

请先阅读当前项目的目录结构、package.json、数据库 Schema、认证模块、现有文件上传逻辑和 AI 生成接口，再设计并实现一套安全、可靠、可维护的 Cloudflare R2 存储方案。

## 一、项目背景

- 项目类型：AI 图片 / 视频生成 SaaS
- 技术栈：Next.js 16、React 19、TypeScript、PostgreSQL
- 部署平台：Vercel
- 对象存储：Cloudflare R2
- AI 服务：第三方图片 / 视频生成 API
- 目标：用户上传的图片、AI 生成的图片和视频都可以可靠保存到 R2

必须遵循以下原则：

1. 优先复用现有项目架构，不随意重构。
2. 使用 AWS SDK v3 操作 R2。
3. 不将 R2 密钥暴露到浏览器。
4. 不依赖第三方 AI 平台的临时文件链接。
5. 区分公开文件和私有文件。
6. 确保文件上传、查询、删除都有正确的权限控制。

## 二、R2 环境变量

使用以下变量：

R2_ACCOUNT_ID=
R2_ACCESS_KEY_ID=
R2_SECRET_ACCESS_KEY=
R2_BUCKET_NAME=
R2_PUBLIC_URL=

R2 S3 Endpoint 格式：

https://{R2_ACCOUNT_ID}.r2.cloudflarestorage.com

AWS SDK region 使用 auto。

如果项目已经使用 STORAGE_* 环境变量，请优先兼容现有命名，不要创建重复配置。

要求：

- 提供 .env.example 示例
- 检查必填环境变量
- 所有密钥仅在服务端使用
- 禁止使用 NEXT_PUBLIC_ 暴露敏感密钥
- 不要将 .env.local 提交到 Git
- 不要在日志中输出密钥或完整预签名 URL

## 三、封装 R2 存储服务

安装：

@aws-sdk/client-s3
@aws-sdk/s3-request-presigner

创建独立的存储服务模块，提供：

1. uploadFile：服务端上传文件
2. getPresignedUploadUrl：生成临时 PUT 上传链接
3. getPresignedDownloadUrl：生成临时 GET 下载链接
4. deleteFile：删除文件
5. getPublicUrl：获取公开文件访问地址
6. objectExists：检查文件是否存在

要求：

- 使用 TypeScript
- 使用 AWS SDK v3
- 文件名使用 UUID 等随机 ID
- 使用合理的对象路径
- 正确处理 Content-Type
- 统一异常处理
- 合理设置超时
- 不能在每次请求中重复创建不必要的客户端
- 禁止通过任意用户输入直接指定其他用户的文件 Key

建议对象路径：

uploads/{userId}/{uuid}.{ext}
generated/images/{userId}/{uuid}.{ext}
generated/videos/{userId}/{uuid}.{ext}
temp/{userId}/{uuid}.{ext}

## 四、用户直接上传

实现以下流程：

1. 用户登录后选择图片。
2. 前端向服务端申请上传。
3. 服务端检查用户身份、上传配额、文件类型和大小限制。
4. 服务端生成随机 Object Key 和短期有效的 PUT 预签名 URL。
5. 浏览器直接上传文件到 R2。
6. 前端通知服务端上传完成。
7. 服务端通过 HeadObject 校验对象是否存在、实际大小和 Content-Type。
8. 必要时检查文件真实格式和安全性，再确认文件可用于业务。
9. 将文件元数据保存到 PostgreSQL。

安全要求：

- 限制文件类型和大小
- 上传签名有效期建议 5 分钟
- 配置 R2 CORS，仅允许可信前端 Origin
- 服务端必须验证文件所有权
- 上传接口需要限流
- 不允许客户端指定任意 Object Key
- 对敏感文件保持私有访问
- 不能仅依赖文件扩展名或前端 Content-Type 判断文件安全性

注意：预签名 PUT URL 不能天然强制文件大小上限，需要在上传后验证；对不合规文件应删除并拒绝确认。

## 五、AI 生成文件转存

AI 图片或视频生成成功后：

1. 获取第三方 AI 平台返回的文件地址。
2. 校验地址来源，避免 SSRF。
3. 仅允许可信供应商域名或经过验证的下载地址。
4. 设置下载超时、最大文件大小和重定向限制。
5. 采用流式传输或适当的分块方案，避免大视频全部加载到内存。
6. 上传到 Cloudflare R2。
7. 校验上传成功。
8. 更新数据库中的文件状态和 Object Key。
9. 返回可访问的文件地址或授权下载接口。

注意：

- 不能直接将第三方临时 URL 当作最终文件地址。
- 视频转存要考虑 Vercel Serverless 执行时间和内存限制。
- 大文件应采用后台任务、可靠队列或其他适合长时间运行的执行环境。
- 异步任务必须支持重试和幂等，避免重复扣费、重复保存。
- R2 上传失败时不能把任务标记为完成。
- 保留错误状态，允许后续重试。

## 七、文件访问与安全

公开文件：

- 可以使用 R2 自定义域名
- 例如 https://cdn.example.com
- 适合明确允许公开访问的图片、视频

私有文件：

- 使用短期 GET 预签名 URL 或鉴权代理
- 必须验证用户身份和文件所有权
- 不允许直接拼接公开 CDN 地址绕过鉴权

特别注意：

- R2 S3 预签名 URL 使用 R2 S3 API Endpoint。
- 不能直接把 S3 预签名 URL 的域名替换成自定义 CDN 域名。
- 不要把整个存储桶公开后再尝试仅靠前端隐藏私有文件。
- 如需同时支持公开和私有文件，应设计清晰的存储隔离与访问策略。
