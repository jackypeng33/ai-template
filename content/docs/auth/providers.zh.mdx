## 邮箱 + 密码

默认启用。用户使用邮箱、姓名和密码注册。

### 邮箱验证

当前 Better Auth 未设置 `requireEmailVerification`。如需在登录时强制验证，可在 `lib/auth.ts` 中配置：

```typescript
emailAndPassword: {
  enabled: true,
  requireEmailVerification: true,
}
```

### 密码重置

密码重置流程：

1. 用户在 `/forgot-password` 请求重置
2. 系统生成 token（存储在 `passwordResetToken` 表，1 小时过期）
3. 发送重置邮件
4. 用户在 `/reset-password?token=...` 设置新密码

## Google OAuth

Google 登录是可选项。只有同时配置 `AUTH_GOOGLE_ID` 和 `AUTH_GOOGLE_SECRET` 时，starter 才会启用该提供商。

### 设置

1. 在 [Google Cloud Console](https://console.cloud.google.com/) 创建 OAuth 凭据
2. 设置授权重定向 URI：`{YOUR_URL}/api/auth/callback/google`
3. 添加到 `.env.local`（或部署平台的服务端环境变量）：

```ini
AUTH_GOOGLE_ID="your-client-id"
AUTH_GOOGLE_SECRET="your-client-secret"
```

## GitHub OAuth

GitHub 已集成。`AUTH_GITHUB_ID` 和 `AUTH_GITHUB_SECRET` 均非空时启用，与 Google 独立控制。通用登录页、注册页和 `/rap` 弹窗均隐藏未配置的提供商。

1. 在 GitHub Settings → Developer settings → OAuth Apps 创建 OAuth App，建议开发和生产分别创建。
2. 本地回调配置 `http://localhost:3000/api/auth/callback/github`，生产配置 `https://你的域名/api/auth/callback/github`。
3. 在 `.env.local` 或部署平台服务端环境变量中填写，然后重启或重新部署：

```ini
AUTH_GITHUB_ID="your-client-id"
AUTH_GITHUB_SECRET="your-client-secret"
```

`BETTER_AUTH_URL`、`NEXT_PUBLIC_APP_URL` 和 `BETTER_AUTH_TRUSTED_ORIGINS` 应与网站来源一致。密钥仅在服务端保存。现有 Better Auth catch-all 接口处理回调，无需新增数据库迁移。

GitHub 内置提供商请求 `read:user` 和 `user:email` 权限，包含私有邮箱查询。无法取得可用邮箱时拒绝认证（`email_not_found`），不伪造占位邮箱。已有账号的关联遵循 Better Auth 默认的已验证邮箱规则，不添加可信提供商绕过逻辑。

首次创建用户通过 `databaseHooks.user.create.after` 发放 300 注册积分，沿用现有余额与流水事务。再次登录或关联已有账号不会再次创建用户或发放奖励。发放失败会记录日志，尚无自动重试。`/rap` 在 OAuth 跳转前保存照片草稿，登录后返回 `/rap`，不会自动购买或生成。

配置后验证首次注册、重复登录、私有邮箱、同邮箱已有账号关联、取消授权和 Rap 草稿恢复。自动化测试模拟 GitHub HTTP；真实凭证和回调地址仍需受控端到端验证。
